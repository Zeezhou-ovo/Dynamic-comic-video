# 音频驱动与时间轴同步

配音是每个分镜的主时间轴。先生成或导入实际配音，再取得时长或时间戳，随后确定字幕、嘴型、关键词动作、反应停顿与 CUT。禁止先随意安排动画，再强行匹配声音。

## 固定顺序

```text
台词 → 配音 → 语音时间戳 → 字幕 → 嘴型区间 → 关键词 → 动作 → 反应停顿 → CUT
```

镜头进入后先保留建立时间，通常约 0.1–0.5 秒，按剧情调整。角色只有在实际发声区间运行嘴型；语音停顿或结束时嘴型立即稳定。字幕不得提前显示未说出的内容，较长台词按语义、标点和关键词拆成多个字幕单元。

## 事件规则

一条普通台词通常安排 0–2 个关键词动作。动作必须绑定台词节点或剧情事件，例如强调关键词时轻微抬头或一次手势，其余时间保持稳定。重要信息先让听者产生表情或视线反应，再开始说话；台词结束后保留 0.2–0.8 秒的反应停顿，具体时长由情绪和 CUT 原因决定。

反应镜头可以没有台词。无对白不等于删除镜头：沉默、眼神变化或尴尬停顿本身可以承担叙事功能。CUT 由说话者改变、观察对象改变、新信息、情绪变化、笑点反应或当前台词完成决定，不由固定秒数决定。

## 统一事件时间轴

每个镜头尽量在 `motion_plan.json` 的 `timeline` 中统一记录以下字段：

```json
{
  "scene_id": "scene_chat",
  "duration_frames": 72,
  "audio": "audio/line_01.wav",
  "audio_start_frame": 8,
  "subtitle_events": [
    {"start_frame": 8, "end_frame": 22, "text": "可靠消息！"},
    {"start_frame": 26, "end_frame": 66, "text": "下午要开新生大会！"}
  ],
  "speech_intervals": [
    {"start_frame": 8, "end_frame": 66, "speaker": "tangguo"}
  ],
  "action_events": [
    {
      "event_id": "emphasis_01",
      "trigger": "speech",
      "keyword": "可靠消息",
      "start_frame": 8,
      "peak_frame": 12,
      "settle_frame": 20,
      "end_frame": 24,
      "description": "轻微抬头后回稳"
    }
  ],
  "expression_events": [],
  "blink_events": [{"frame": 44, "description": "一次自然眨眼"}],
  "sound_events": [],
  "cut_at_frame": 72
}
```

字幕、嘴型、动作、音效和 CUT 必须引用同一时间轴，不能在不同组件中各自维护冲突的时间定义。时间统一使用帧；音频时间戳换算为帧时使用项目 `fps`，并记录取整方式。

## 输出前检查

- 镜头开始后是否有合理建立时间？
- 字幕是否从实际发声开始，是否拆分了长句中的语义停顿？
- 嘴型是否只覆盖 `speech_intervals`，停顿和结尾是否闭合？
- 关键词动作是否发生在有意义的词或事件上，且每句不超过两个主要动作？
- 听者是否先反应再说话？
- 台词结束后是否保留了必要的反应时间？反过来，台词前后是否存在超过约 1 秒、既无台词也无表演事件的空白？
- 对白之间是否有底噪或音乐床，而不是数字静音？交付前用 `deliver.py` 查看响度报告。
- CUT 是否由叙事变化触发？
- 配音、字幕、嘴型、动作、音效和 CUT 是否来自同一 `timeline`？

最终节奏应呈现“说话 → 停顿 → 反应 → CUT”。声音决定节奏，台词决定嘴型，语义决定动作，情绪决定停顿，叙事决定 CUT。
