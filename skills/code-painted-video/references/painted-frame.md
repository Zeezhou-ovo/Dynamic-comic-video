# 代码逐帧绘制

本 Skill 用代码绘制角色和场景的每一帧，再截帧编码。它与 `dynamic-comic-video` 的 `sequential-comic` Remotion 管线是独立路线，不共用 master、对齐图层或 `motion_plan` 0.3。不要把另一条路线的 `prepare`、`preview.py`、`deliver.py` 宣称为已支持本路径；使用本 Skill 自己的预览、截帧和交付记录。可从 `assets/painted-frame-starter/` 复制最小工程。

## 目标与输入

- 保留用户原始故事、角色身份和风格选择。参考图用于提取发型、服装、颜色、比例和辨识锚点；复杂角色可以按用户要求转译成可绘制的漫画形象，但不能声称达到原图的肖像精度。
- 先写清 Narrative Beats、镜头时长、主要动作的准备／执行／停顿、画布尺寸、帧率和声音来源。没有对白时不强加嘴型或配音。
- 当用户指定参考视频，提取其笔触、画面组织和运动规律；不要照搬参考视频的独有剧情、人物或素材。

## 绘制合同

每个镜头实现可随机访问的 `drawWorld(t)` 或等价函数。人物、道具、背景采用同一画布坐标、透视、调色板、笔刷和纸纹；角色的脚、手、道具与环境接触点应共享坐标关系。不要以生成的人物立绘、整张场景图或几张图片切换替代绘制；用户明确授权使用图片素材时，仍需让关键表演由代码实际完成，并如实说明哪些元素来自图片。

将表演拆成可绘制的部件与参数，如头部、发梢、眼睑、手臂、衣袖、腿、道具位置。由绝对时间计算姿势，不依靠上一帧累积状态；任意顺序调用同一个 `t` 都应得到相同画面。需要手绘笔触的轻微变化时，按离散 boil 帧播种随机数，例如 `randomSeed(base + floor(t * boilFps))`，而角色位置和动作仍按目标帧率连续计算。不要用全身周期漂浮或单纯镜头推拉冒充表演。

推荐将纸张、底色、填色、水彩纹理、墨线、文字与最终颗粒合成分层组织在**同一绘制程序**里。分层是绘制顺序，不意味着必须生成互不对齐的独立图片。默认使用 p5.js＋p5.brush；用户指定等价代码绘制框架时遵从其选择，并在项目说明中记录。

## 预览与视觉复核

在全片截帧前，渲染每个动作的准备、接触、峰值、回稳以及镜头交接两侧的静帧。随后查看实际连续播放，重点检查：

- 角色身份是否持续可辨，动作是否有明确事件原因；走路不能像滑动。
- 脚底、手持道具、投影、遮挡、透视与光向是否和场景一致。
- 笔触、水彩密度、线粗和颗粒是否统一；不能让人物像贴在另一种画风的背景上。
- 中间帧、字幕和声音节奏是否成立；首末帧合格不代表动作过程合格。

发现上述问题时先修绘制参数或共享场景坐标，再重绘受影响帧；不要用调色或模糊单独掩盖错误接触与遮挡。

## 截帧与交付

提供 `renderAt(t)` 或等价的可调用接口，由无头浏览器按固定 fps 逐帧捕获。编码前确认期望帧数全部存在、文件内容与扩展名一致，再用 FFmpeg 合成视频及已授权音轨。检查输出的实际时长、分辨率、帧率、音轨和代表性画面；记录所用浏览器、绘制库、编码参数及可重现命令。机器专属可执行文件路径应通过参数或配置提供，不写死为通用模板。

源代码、参考、音频、帧文件和 MP4 放在仓库外的独立项目目录；不要把用户私有素材提交进 Skill 仓库。交付时说明实际绘制程度、角色造型简化之处和未解决的视觉问题。若未完成逐帧视觉复核，不要声称达到参考片的动画质量。
